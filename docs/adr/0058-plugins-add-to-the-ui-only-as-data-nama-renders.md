# Plugins add to the UI only as data Nama renders

Jellyfin's most popular UI plugins inject JavaScript through File Transformation and break on every release, and their pages stop looking like Jellyfin. So a Plugin adds to Nama's web app only by answering, with data, at an Extension Point the Kernel serves, and Nama draws every pixel and word around it; a Plugin never supplies JavaScript, HTML, CSS or an iframe. Each place in the UI is an ordinary Extension Point, one contract service with its own version (ADR 0043), with no umbrella "UI Extension Point". The first is the Home row: work on it waits until Continue Watching (#882, #904) and Library browse (#884) settle, so its contract isn't fixed around a home page still moving.

A Plugin serving the Home row point answers two calls, each made for one User with a 2-second timeout and no cache. The first lists its rows for that User: up to 3, each a stable key and a plain-text heading of at most 40 characters, which may differ per User ("Because you watched Dune"), so rows aren't declared in the Manifest. The second gives one page of one row's External IDs. The web app lists the rows, then fetches each row's pages on its own, as it does Continue Watching, so a slow or failing row holds up only itself; a failed or timed-out row list drops that Plugin's rows, a failed page drops that row. The client RPC pages with `nama.v1.PageRequest` and `PageResponse` from `proto/nama/v1/page.proto` (ADR 0055), with no `total_size`, since a row such as "Trending" has no count. The contract can't import them (ADR 0041), so the page call takes `page_size` and `page_token` and answers `next_page_token`, as `list_titles` and the blob store do; the Kernel passes the size through and wraps the Plugin's token, with the Plugin and row key, in its own client token, refusing one replayed against another row with `REFUSAL_REASON_PAGE_TOKEN_INVALID`. The Kernel returns a page short when it drops titles from it, keeping `next_token`, rather than asking the Plugin again inside the timeout, and leaves out a row whose first page comes back empty. The Plugin sends only External IDs, never names, posters or URLs: the Kernel resolves a title on the Server from its Library and a missing one through the Server's title sources, as a Request does, and drops what it can't resolve. So the browser never loads from a host a Plugin picked, and every title looks like every other. A row may hold missing titles, which the User can Request from them, so a discovery row can be a Plugin; for a User without the Request Permission the Kernel drops them, and a missing title with an open Request shows its state. PRODUCT.md's first principle names this exception. The Kernel's rows come first, then each Plugin's in the order the Plugins were enabled. A Plugin's failures show in the log and on the Plugins page, never on the home page.

## Considered Options

- **No UI extension**: rejected. Home Sections and Custom Tabs show the demand, and without a declared point it moves to forks and injection.
- **Plugin-supplied JavaScript or iframes**: rejected. It repeats Jellyfin's breakage, lets a Plugin run code in every User's session, and gives up PRODUCT.md's look and words.
- **Only titles on the Server in a Plugin's row**: rejected. A discovery row is wanted, and Requests are part of browsing; dropping missing titles for Users who can't Request keeps them from dead ends.
- **One call returning every row and its titles**: rejected. The slowest Plugin would hold up the home page, and a row couldn't page.
- **Refilling short pages**: rejected for now. It multiplies Plugin calls inside one timeout; revisit if rows that look empty show up in practice.
- **Plugin-supplied names and posters**: rejected. The browser would load from hosts the Admin never granted, and a Plugin could show anything under a title's name.
- **Admin pages from a Plugin-supplied schema**: dropped. Plugin settings and Personal settings (ADR 0046) already render from the Manifest; a further admin point waits for a Plugin they can't serve.

## Consequences

- Admins ordering rows, and Users reordering and hiding any row, Kernel or Plugin, is #999.
- A title-page panel (text, links, the Request action) is the likely next point; it gets its own decision when a Plugin needs it.
