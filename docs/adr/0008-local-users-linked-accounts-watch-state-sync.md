# Local Users, optional Hub Accounts, and how Watch State syncs

Every Server has its own Users, who work offline. A User can optionally be linked to a Hub Account. Only linked Users get Watch State sync, remote discovery, Watchlists and recommendations (unlike Plex, which requires an account to use the server at all). Each Server is the source of truth for anything watched on it and pushes each change to the Hub. The Hub keeps a merged copy for each Account, and per title the most recent timestamp wins. A Server pulls that copy when a User is first linked and after a rescan, which is how Watch State survives moving or rebuilding a Library. The push is best effort: a change the Server commits just before it stops, before the Hub Plugin queues it, is never pushed as it happened. One that leaves Watch State on the Server, as playing or marking played does, is newer than anything a pull brings, so the Server keeps it and sends it with the Movie's or Episode's next change, or when it next pushes a Linked User's whole Watch State, as each look at a Linked Server's or User's Link does. One that forgets Watch State, as marking unplayed does, leaves nothing to keep, so the next pull can bring the Hub's older state back. The window is small, so no catch-up closes it until lost changes show up in practice. The Hub keys Watch State by external metadata IDs (TMDB, or TMDB/TVDB plus season and episode), never by Server-internal IDs. Unmatched items never leave their Server.
