# Local Users, optional Hub Accounts, and how Watch State syncs

Every Server has its own Users, who work offline. A User can optionally be linked to a Hub Account. Only linked Users get Watch State sync, remote discovery, Watchlists and recommendations (unlike Plex, which requires an account to use the server at all). Each Server is the source of truth for anything watched on it and pushes each change to the Hub. The Hub keeps a merged copy for each Account, and per title the most recent timestamp wins. A Server pulls that copy when a User is first linked, whenever they sign in or their Link is read, and after each Scan's Matching, which is how Watch State survives moving or rebuilding a Library. The Hub keys Watch State by external metadata IDs (TMDB, or TMDB/TVDB plus season and episode), never by Server-internal IDs. Unmatched items never leave their Server.

The push is best effort. A change the Server commits just before it stops, or one the Hub Plugin fails to queue, isn't pushed on its own. One that leaves Watch State on the Server, as playing or marking played does, is newer than what the Hub held before it, so a pull keeps it, and it reaches the Hub with the Movie's or Episode's next change, or with the next push of the User's whole Watch State, which reading the Server's or a User's Link starts. One that forgets Watch State, as marking unplayed does, leaves nothing to send again, so the Hub and other Servers keep the older Watch State until the title's next change; the Server keeps when it was marked unplayed, so its own next pull doesn't bring it back. Ponytail ceiling: the window is small, so a catch-up in the Hub Plugin waits until lost changes show up in practice.
