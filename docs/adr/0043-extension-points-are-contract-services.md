# Extension Points are contract services

Each Extension Point an Installed Plugin can serve is one proto service under `nama.plugin.v1`, such as `nama.plugin.v1.MovieFulfillerService`, whose rpcs name the WASM exports the Kernel calls there (`fulfill`, `progress` and so on) and the messages each takes and returns. An export that returns nothing returns an empty message, which encodes to zero bytes, so today's exports stay valid. Each service has a semver version of its own, starting at 1.0.0, listed in `SERVICES` in [`nama-plugin-proto`](../../crates/nama-plugin-proto/src/lib.rs). A Manifest names the points it serves in `points`, each by the service's full name and a Cargo-style requirement such as `^1.0.0`. A Server refuses at load, in plain words, a Plugin naming a service it doesn't serve (`its Manifest names {service}, an Extension Point this Server doesn't serve`) or a requirement that doesn't parse or that the version it serves doesn't meet (`it wants {service} {wants}, and this Server serves {version}`). The `ObservePoint` and `ProvidePoint` enums and the Manifest's `observers` and `providers` fields are dropped without compatibility: their numbers and names are reserved, and `CONTRACT_VERSION` stays 0.3.0, which no released Server has had, so a Plugin built against it before this change reads as naming no points. `CONTRACT_VERSION` keeps the Manifest, the messages more than one service shares, such as `Request`, and what the Kernel gives a Plugin; a change only one service's Plugins see moves that service's version alone. A Server that changes one point, such as a title source, then still loads every Plugin serving only the others, and the contract can grow a point without asking every Plugin to rebuild.

## Considered Options

- **An enum value per point, as before**: rejected. A value names a point but can't say which version of it a Plugin was built for, so any change to one point's exports had to move the whole contract's version.
- **Services, with one version for all of them**: rejected. Every point's change would refuse Plugins serving only the others, which grows worse as points such as a title source or a blob store join.

## Consequences

- The proto services are declarations for Plugin authors and for the Kernel's table of points; buf's lint for rpc message names and reuse is off for `nama/plugin`, since these are exports, not RPCs.
- The Kernel serves each point at one version; serving two majors of a point at once waits until a point needs it.
- The same check at load refuses a Manifest whose `movie_id_namespaces` or `show_id_namespaces` holds a malformed namespace, rather than leaving the Kernel to fail its Requests later.
- The Kernel converts client API Events to contract messages where it calls a Plugin (`crates/nama-server/src/plugins/contract.rs`), so Built-in Notifiers and Observers receive only what the contract carries. They no longer receive `RequestProgress`, `FollowedShowCreated`, `FollowedShowRequesterAdded`, `FollowedShowStateChanged`, `FollowedShowCancelled`, `FollowedShowRequesterRemoved` or `FollowedShowWithdrawn`, which have no contract message; they gain them when the contract does.
