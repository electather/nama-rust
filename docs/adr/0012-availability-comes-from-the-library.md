# Request availability comes from the Library, not from Sonarr/Radarr

The Kernel owns every Request and its states (`Pending → Approved | Declined → Processing → Partially Available → Available`, plus `Failed`). The Fulfiller only hands the work off. A Request moves to Partially Available or Available only when the Server's own Library scan Matches the requested Movie or Episodes. Only a Request its Fulfiller has becomes Partially Available; one not yet handed off keeps its state, so it can still be decided, handed off or retried, until a scan Matches all of it and makes it Available. Seerr has to ask Sonarr/Radarr and the media server to find this out; because nama has requests built in, the Library is the single source of truth and there's nothing to poll for availability.

Download progress is the one thing the Kernel asks a Fulfiller for: while any Request its Fulfiller has isn't Available yet (Processing or Partially Available), it asks every 60 seconds, as Seerr does, so Users can watch a Request move. Progress is only shown, never stored, and never changes a Request's state.
