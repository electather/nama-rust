## Users

Users, Devices and their sessions (`../users.rs`), the Users a Device is signed in as and switching between them (`device_users.rs`, ADR 0106), what their names may hold and the key a User's, and a Library's, is unique under (`names.rs`), the Permissions a User holds (`permissions.rs`), setting and checking passwords through the Authenticator, and Switch PINs (`passwords.rs`), changing other Users' Permissions and cap for remote playback, the default ones, and deleting Users (`managing.rs`), Invites (`invites.rs`), deleting expired Devices and Invites (`expired.rs`), whether a User has a way in, their Account among them, and creating Users from Accounts (`accounts.rs`), signing in (`sign_in.rs`, with who a Device signs in as in `proved.rs`, Sign-in Codes in `sign_in_codes.rs`, the Setup Code and random codes in `codes.rs`, the sign-in limits and wrong Switch PINs in `rate_limits.rs` and Device names and kinds in `device_names.rs`), the session layer over HTTP (`sessions.rs`), which Libraries each User sees (`library_access.rs`), each User's Maximum Age (`maximum_age.rs`), Personal settings, the kinds of Request notification each User turned off (`notification_preferences.rs`), each User's inbox of the Request notifications they were told (`inbox.rs`), each User's Home layout over the default (`home_layout.rs`), and whose Requests and playing a User sees (`seeing.rs`: `User::whose_requests`, `User::whose_playing`, `may_see`, `is_requester`).

- **Guessable requests go through `SignIn` (`sign_in.rs`).** It lets an attempt through before reading a User or a secret, and un-counts it the moment the secret checks out; a failure after that, an input check before it, or a refusal any client could predict, such as Setup on a set-up Server, is no guess. Sign-in Codes count only an unknown or expired code. A Switch PIN is the exception to reading after letting through: whose Switch PIN it is and whether they set one are read first, since the Device already lists its Users, and a try then counts until it checks out; a missing one doesn't.
- **Password work is bounded.** Every Authenticator call on a password, and every Switch PIN's hashing, runs through `blocking` in `passwords.rs`, at most 4 at once, so a burst of sign-ins, known names or not, holds at most 4 hashes' 19 MiB.
- **One `Users` per Server.** Startup in `lib.rs` builds it and hands out clones. A `Users` built with `new` has its own sign-out, Permission-change and Library access-change channels and its own `Linking`, which remembers its own Links and tells only its own followers, so it neither hears nor tells another, and an Events subscription would outlive a sign-out, Permission change or Library access change made through it. Production code builds one only there and in `main.rs`'s Setup Code check before serving; test helpers may build their own. `../../tests/structure.rs` checks it.
- **One owner for the inbox:** only `inbox.rs` reads or writes `inbox`, tests included; `../events.rs` picks whose inbox a notification goes in, as it does for Notifiers.
- **One owner for Library access:** only `library_access.rs` reads or writes `user_libraries`, tests included, and `library_access` alone answers which Libraries a User sees, as `maximum_age` does which titles their Maximum Age lets through. Every place that hands a User titles or plays them asks both, so a Plugin can't leak a title from a Library they don't see or over their Maximum Age.
- **One owner for Personal settings:** only `personal_settings.rs` reads or writes `personal_settings`, tests included; values are secrets in logs, and a secret never goes back to a client (ADR 0046).

### Neighbours

- Uses: `db`, `page` (paging the inbox), `plugins` (`ExtensionPoints`, the Authenticator), `link` (whether a User is Linked, inviting a User and finishing a sign-in with an Account; `Users` holds the Server's one `Linking`), `nama-forwarded` (`RequestSource`) and `server_settings` (the default Home layout a User's applies over, and `PlaybackLimit`, which a cap for remote playback is) and `content_ratings` (`MaximumAge`).
- Used by: `api` (`library_access`, sessions, `SignIn`, `SetupCode`, the Users parts, Invites, Home layouts, the inbox), `plugin_settings` (saving and reading a User's Personal settings, deleting a removed Plugin's, and dropping an uninstalled Plugin's rows from `UserHomeLayout`s), `connections` (`random_secret`), `events` (Personal settings and turned-off notifications for Notifier deliveries, `every_user` and storing in the inbox, `whose_requests`, `whose_playing`, `may_see` and `LibraryAccess`), `home_rows` (a User's Personal settings for their own Home rows, `split_personal_settings`, `library_access` and `maximum_age`), `playback` (a User's cap for remote playback, `remote_cap`, `library_access` and `maximum_age`), `requests` (`whose_requests`, `may_see`, `is_requester`, `library_access` and `maximum_age`), `library` (`name_key`, and a User's Personal settings for a Watch sync Plugin with `personal_settings_of` and `split_personal_settings`), `watch_sync` (whose Watch State each Watch sync Plugin imports, `personal_settings_recipients`), startup in `lib.rs` and `main.rs`, `automation` (which holds the Server's `Users` for `list_users` and `list_devices`, and runs `delete_expired_sign_ins`), `browse` (the `User` a title's page is read for, `library_access`, `maximum_age`, and its tests), `sync` (`Users::list`, whose Users each trigger may sync, and the `Linking` it follows), and the tests of `library`.
