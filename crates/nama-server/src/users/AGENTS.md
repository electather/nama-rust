## Users

Users, Devices and their sessions (`../users.rs`), what their names may hold and the key a User's, and a Library's, is unique under (`names.rs`), the Permissions a User holds (`permissions.rs`), setting and checking passwords through the Authenticator (`passwords.rs`), changing other Users' Permissions, the default ones, and deleting Users (`managing.rs`), Invites (`invites.rs`), deleting expired Devices and Invites (`expired.rs`), signing in (`sign_in.rs`, with who a Device signs in as in `proved.rs`, Sign-in Codes in `sign_in_codes.rs`, the Setup Code and random codes in `codes.rs`, the sign-in limits in `rate_limits.rs` and Device names and kinds in `device_names.rs`), the session layer over HTTP (`sessions.rs`), Personal settings, the kinds of Request notification each User turned off (`notification_preferences.rs`), each User's Home layout over the default (`home_layout.rs`), and whose Requests and playing a User sees (`seeing.rs`: `User::whose_requests`, `User::whose_playing`, `may_see`, `is_requester`).

- **Guessable requests go through `SignIn` (`sign_in.rs`).** It lets an attempt through before reading a User or a secret, and un-counts it the moment the secret checks out; a failure after that, an input check before it, or a refusal any client could predict, such as Setup on a set-up Server, is no guess. Sign-in Codes count only an unknown or expired code.
- **One `Users` per Server.** Startup in `lib.rs` builds it and hands out clones. A `Users` built with `new` has its own sign-out and Permission-change channels, so it neither hears nor tells another, and an Events subscription would outlive a sign-out or Permission change made through it. Production code builds one only there and in `main.rs`'s Setup Code check before serving; test helpers may build their own. `../../tests/structure.rs` checks it.
- **One owner for Personal settings:** only `personal_settings.rs` reads or writes `personal_settings`, tests included; values are secrets in logs, and a secret never goes back to a client (ADR 0046).

### Neighbours

- Uses: `db`, `plugins` (`ExtensionPoints`, the Authenticator), `nama-forwarded` (`RequestSource`) and `server_settings` (the default Home layout a User's applies over).
- Used by: `api` (sessions, `SignIn`, `SetupCode`, the Users parts, Invites, Home layouts), `plugin_settings` (saving and reading a User's Personal settings, deleting a removed Plugin's, and dropping an uninstalled Plugin's rows from `UserHomeLayout`s), `connections` (`random_secret`), `events` (Personal settings and turned-off notifications for Notifier deliveries, `whose_requests`, `whose_playing` and `may_see`), `home_rows` (a User's Personal settings for their own Home rows), `playback`, `requests` (`whose_requests`, `may_see` and `is_requester`), `library` (`name_key`), startup in `lib.rs` and `main.rs`, `automation` (which holds the Server's `Users` for `list_users` and `list_devices`, and runs `delete_expired_sign_ins`), `browse` (the `User` a title's page is read for, and its tests), and the tests of `library`.
