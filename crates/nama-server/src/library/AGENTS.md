## Library

What a Library holds: its contents, its settings (`libraries.rs`), asking its title sources and Recognisers, artwork, Custom Images, the images beside its media (`local_images.rs`) and Watch State.

- **Parts.** A name two parts share, or one that reads only beside its module, is re-exported under a clear name (`LibraryKind`, `WatchStateKind`, `WatchedTitle`, `LibraryError`, `LibraryShow`, `SourceShow`, `artwork_url`). `Artwork` and `ArtworkError` are `pub` so the integration tests reach them as `nama_server::Artwork`. `titles` finds a title of a Library by any of its ids (`Titles`, `TitleTarget`, `NotFound`) for Browse and the Scanner's deletes, `scan_locks` holds each Library's scan lock, `country_tags` reads a Show name's country tag, and `versions` holds `PARSER_VERSION` and `METADATA_VERSION`, all here so the Scanner and Matching share them without calling up.
- **Only `Scanner::new` makes `ScanLocks`.** It hands the same locks to its Matcher, so no Match is fixed under locks a scan doesn't take. The one other maker is the test-only `ScanLocks::for_tests`, for a Matching or Requests test that builds a Matcher without a Scanner. Rust can't limit `ScanLocks::new` to the Scanner without an upward import, so review keeps it to one caller: `git grep -n 'ScanLocks::new'`.
- **One owner for a Library's contents.** Only `contents.rs` and its `contents/` folder read or write `library_files`, `library_items`, `item_matches`, `item_match_ids`, `match_pins`, `title_search` and `local_images`, tests included. Everything else goes through `Contents`. `OWNED_TABLES` in `crates/nama-server/tests/structure.rs` enforces it.
- **Matches make Requests Available in the same write.** A write that stores Matches makes the Matched Movies' and Seasons' Requests Available by calling `requests::make_available` and `make_seasons_available` (ADR 0012). It is the one accepted call up the rows: `ALLOWED_UPWARD` lets through only these two functions, imported by path.
- **A title's preferred id follows its Library's order.** Contents reads name a Movie or Show by `primary_id` in the order of the Library's `title_sources`, read in the same query; only what belongs to no Library, such as a Request, uses `DEFAULT_ORDER`. The title id code is in `contents/ids.rs`.
- **One owner for asking a Library's Recognisers.** `libraries.rs` stores the ids of the Plugins whose Recognisers a Library asks, first asked first, and a new Library lists none (ADR 0050). Only `recognisers.rs` (`Recognisers`) picks and asks a `Recogniser`, each level handing it the method call: it asks those that are enabled, in that order, only for a method each serves, skips one disabled since, logs each failing one once per scan, and records which a scan starts with. The Scanner and Matching ask it at their levels and decide what an answer or `RecogniserFailed` means.
- **Test helpers.** `contents/fixture.rs` is the one in-file fixture other areas' tests build on, as `library::fixture`; `contents/testing.rs` holds what tests read back.
- **One owner for asking the title sources.** Only `title_source.rs` (`TitleSources`) calls a `TitleSource` and decides what its failures mean. Matching, Requests, Artwork and handlers ask it and read its `Unanswered`.
- **Artwork picks from every list.** Artwork picks from every ordered source's artwork list (ADR 0045), by language (the asked one first, but a Backdrop prefers none), then source order, then rating.
- **One owner for Custom Images.** Only `custom_images.rs` reads or writes `custom_images`, tests included, and keys a title's as the per-title rule in `crates/nama-server/AGENTS.md` says, and a Plugin's by the Plugin's id (ADR 0036). A Library's goes with the Library. Browse, Requests, Libraries and Plugins ask it for the URLs to show in place of downloaded images and Manifests' logos.
- **Images beside the media come after Custom Images.** A title's Custom Image goes first, then the image beside its first-added Item's file, or for a Show or Season in its folder (`LocalImageUrls`), then the downloaded one; every place that shows a Movie's, Show's or Season's Poster or Backdrop asks in that order. The Server copies those files into the image store and never writes or deletes them (#732, #1016).
- **One owner for Watch State.** Only `watch_states.rs` reads or writes `watch_states`, tests included, and keys a Movie's or Episode's as the per-title rule in `crates/nama-server/AGENTS.md` says. Browse works out which Movie or Episodes a Version or a marked title stands for and asks `WatchStates`. Browse and Automation both read a title's Watch State under any of its ids (`of_titles`, or every one of a User's with `of_user` for Continue Watching); Browse writes under the preferred id, and marking unplayed forgets every id's (ADR 0042). Every write of a Watch State row clears its `hidden` mark, so hiding from Continue Watching lasts until the User's Watch State of that title next changes (#916); only `hide` sets it.

### Neighbours

- Uses: `db`, `events`, `requests` (the ADR 0012 call), `users` (`name_key`, which Library names are unique under), `plugins` (`ExtensionPoints`), `images`, `server_settings` (`ImageSettings`).
- Used by: `scanner` and `matching` (also `Recognisers`, `ScanLocks`, `country_tag` and `PARSER_VERSION`), `browse`, `playback`, `requests`, `home_rows` (Contents, Libraries), the `api` parts and startup in `lib.rs`.
