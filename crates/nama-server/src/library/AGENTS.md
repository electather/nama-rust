## Library

What a Library holds: its contents, its settings (`libraries.rs`), asking its title sources, artwork, Custom Images and Watch State.

- **Parts.** Each part is a `mod` of `library.rs` that neighbours address by name, such as `library::title_source::TitleSources`; its own files are private modules. `artwork` is public only so the integration tests reach it as `nama_server::artwork`. `scan_locks` holds each Library's scan lock, `country_tags` reads a Show name's country tag, and `versions` holds `PARSER_VERSION` and `METADATA_VERSION`, all here so the Scanner and Matching share them without calling up.
- **Only `Scanner::new` makes `ScanLocks`.** It hands the same locks to its Matcher, so no Match is fixed under locks a scan doesn't take. The one other maker is the test-only `ScanLocks::for_tests`, for a Matching or Requests test that builds a Matcher without a Scanner. Rust can't limit `ScanLocks::new` to the Scanner without an upward import, so review keeps it to one caller: `git grep -n 'ScanLocks::new'`.
- **One owner for a Library's contents.** Only `contents.rs` and its `contents/` folder read or write `library_files`, `library_items`, `item_matches`, `item_match_ids`, `match_pins` and `title_search`, tests included. Everything else goes through `Contents`. `OWNED_TABLES` in `crates/nama-server/tests/structure.rs` enforces it.
- **Matches make Requests Available in the same write.** A write that stores Matches makes the Matched Movies' and Seasons' Requests Available by calling `requests::make_available` and `make_seasons_available` (ADR 0012). It is the one accepted call up the rows: `ALLOWED_UPWARD` lets through only these two functions, imported by path.
- **Private modules.** Contents' files are private modules; neighbours import only what `contents.rs` re-exports, and items inside default to `pub(super)`. The one exception is `pub(crate) mod fixture`, which other areas' tests import as `library::contents::fixture`. The title id code is in `contents/ids.rs`.
- **A title's preferred id follows its Library's order.** Contents reads name a Movie or Show by `primary_id` in the order of the Library's `title_sources`, read in the same query; only what belongs to no Library, such as a Request, uses `DEFAULT_ORDER`.
- **A Library asks its Recognisers in its own order.** `libraries.rs` stores the ids of the Plugins whose Recognisers it asks, first asked first; the Scanner and Matching ask only those that are enabled, in that order, and a new Library lists none (ADR 0050).
- **Test helpers.** `contents/fixture.rs` is the one in-file fixture other areas' tests build on; `contents/testing.rs` holds what tests read back.
- **One owner for asking the title sources.** Only `title_source.rs` (`TitleSources`) calls a `TitleSource` and decides what its failures mean. Matching, Requests, Artwork and handlers ask it and read its `Unanswered`.
- **Artwork picks from every list.** Artwork picks from every ordered source's artwork list (ADR 0045), by language (the asked one first, but a Backdrop prefers none), then source order, then rating.
- **One owner for Custom Images.** Only `custom_images.rs` reads or writes `custom_images`, tests included, and keys a title's by its external id, never an Item or file, and a Plugin's by the Plugin's id (ADR 0036). A Library's goes with the Library. Browse, Requests, Libraries and Plugins ask it for the URLs to show in place of downloaded images and Manifests' logos.
- **One owner for Watch State.** Only `watch_states.rs` reads or writes `watch_states`, tests included, and keys it by a Movie's or Episode's external id, never an Item or file (ADR 0013). Browse works out which Movie or Episodes a Version or a marked title stands for and asks `WatchStates`. Browse and Automation both read a title's Watch State under any of its ids (`of_titles`); Browse writes under the preferred id, and marking unplayed forgets every id's (ADR 0042).

### Neighbours

- Uses: `db`, `events`, `requests` (the ADR 0012 call), `plugins` (`ExtensionPoints`), `images`, `server_settings` (`ImageSettings`).
- Used by: `scanner` and `matching` (also `scan_locks`, `country_tags` and `versions`), `browse`, `playback`, `requests`, the `api` parts and startup in `lib.rs`.
