## Library

What a Library holds: its contents, its settings (`libraries.rs`), asking its title sources and Recognisers, artwork, Custom Images, the images beside its media (`local_images.rs`) and Watch State.

- **Parts.** A name two parts share, or one that reads only beside its module, is re-exported under a clear name (`LibraryKind`, `WatchStateKind`, `WatchedTitle`, `LibraryError`, `LibraryShow`, `SourceShow`). `Artwork` and `ArtworkError` are `pub` so the integration tests reach them as `nama_server::Artwork`. `titles` finds a title of a Library by any of its ids (`Titles`, `TitleTarget`, `NotFound`) for Browse and the Scanner's deletes, and which Library has titles named by id (`OnServer`) for Home rows and Similar titles, `scan_locks` holds each Library's scan lock, `country_tags` reads a Show name's country tag, and `versions` holds `PARSER_VERSION` and `METADATA_VERSION`, all here so the Scanner and Matching share them without calling up.
- **Only `Scanner::new` makes `ScanLocks`.** It hands the same locks to its Matcher, so no Match is fixed under locks a scan doesn't take. The one other maker is the test-only `ScanLocks::for_tests`, for a Matching or Requests test that builds a Matcher without a Scanner. Rust can't limit `ScanLocks::new` to the Scanner without an upward import, so review keeps it to one caller: `git grep -n 'ScanLocks::new'`.
- **One owner for a Library's contents.** Only `contents.rs` and its `contents/` folder read or write `library_files`, `library_items`, `item_matches`, `item_match_ids`, `match_pins`, `title_search`, `title_search_vocab`, `local_images`, `nfo_files`, `title_details`, `title_roles`, `similar_titles` and `box_sets`, the stores ADR 0081 keeps a title's Score, Trailers, Box Set, Roles and Similar titles in once per title, and `episode_air_dates`, kept once per Show the same way, tests included. Everything else goes through `Contents`. `OWNED_TABLES` in `crates/nama-server/tests/structure.rs` enforces it.
- **Matches make Requests Available in the same write.** A write that stores Matches makes the Matched Movies' and Seasons' Requests Available by calling `requests::make_available` and `make_seasons_available` (ADR 0012).
- **A new Segment source or a Match's new ids make Versions due in the same write.** Updating a Library so its Segment sources list a Plugin they didn't calls `playback::make_segments_due` (ADR 0075); a reorder or removal doesn't. A write that changes an Item's Match reads its ids before and calls `playback::title_ids_changed` after, through `contents/ids.rs`. These four functions are the Library's only accepted calls up the rows: `ALLOWED_UPWARD` lets it through only them, imported by path.
- **A Library's titles are derived once.** Contents reads that list a Library's titles build on `matched_items` and `library_titles` in `contents/titles_sql.rs`. The derivation alone picks the preferred id in SQL, in the Library's `title_sources` order (ADR 0044), and owns "Matched only", the title's first Item and its added time; only Automation's list, of Movies and Episodes on `matched_items` alone, keeps its own first Version and added time, as the Kernel functions in `automation.proto` promise. Rust `primary_id` in `contents/ids.rs` is for what belongs to no Library, such as a Request (`DEFAULT_ORDER`); `primary_id_in` only for reads that start from a Version or Item, such as `matched_to`.
- **One owner for asking a Library's Recognisers.** `libraries.rs` stores the ids of the Plugins whose Recognisers a Library asks, first asked first, and a new Library lists none (ADR 0050). Only `recognisers.rs` (`Recognisers`) picks and asks a `Recogniser`, each level handing it the method call: it asks those that are enabled, in that order, only for a method each serves, skips one disabled since, logs each failing one once per scan, and records which a scan starts with. The Scanner and Matching ask it at their levels and decide what an answer or `RecogniserFailed` means.
- **Test helpers.** `contents/fixture.rs` is the one in-file fixture other areas' tests build on, as `library::fixture`; `contents/testing.rs` holds what tests read back; `title_source/scripted.rs` is the title source they script, as `library::scripted`.
- **One owner for asking the title sources.** Only `title_source.rs` (`TitleSources`) calls a `TitleSource` and decides what its failures mean. Matching, Requests, Artwork and handlers ask it and read its `Unanswered`.
- **One owner for asking the Similar sources.** Only `similar_sources.rs` (`SimilarSources`) calls a `SimilarSource`, and its `merged` alone orders what they answer (ADR 0084). Matching asks it before storing a Match, a Found page asks it live, and Browse reads the stored answers back through `Contents::similar`.
- **Artwork picks from every list.** Artwork picks from every ordered source's artwork list (ADR 0045), by language (the asked one first, but a Backdrop prefers none, and the titled Backdrop takes only the asked one), then source order, then rating.
- **One owner for Custom Images.** Only `custom_images.rs` reads or writes `custom_images`, tests included, and keys a title's as the per-title rule in `crates/nama-server/AGENTS.md` says (ADR 0036). A Library's goes with the Library. `ShownImages` asks it for the URLs titles and Libraries show in place of downloaded images.
- **Images beside the media come after Custom Images.** A title's Custom Image goes first, then the image beside its first-added Item's file, or for a Show or Season in its folder (`LocalImageUrls`), then the downloaded one. Only `ShownImages` in `shown_images.rs` answers that order: every place that shows a Movie's, Show's, Season's or Library's image asks it, and says whether its downloaded image is stored or offered (`Downloaded`). The titled Backdrop has no such slots, so it is only ever the downloaded one (#1339). The Server copies those files into the image store and never writes or deletes them (#732, #1016).
- **One owner for Watch State.** Only `watch_states.rs` reads or writes `watch_states`, tests included, and keys a Movie's or Episode's as the per-title rule in `crates/nama-server/AGENTS.md` says. Browse works out which Movie or Episodes a Version or a marked title stands for and asks `WatchStates`. Browse and Automation both read a title's Watch State under any of its ids (`of_titles`, or every one of a User's with `of_user` for Continue Watching); Browse writes under the preferred id, and marking unplayed forgets every id's (ADR 0042). Every write of a Watch State row clears its `hidden` mark, so hiding from Continue Watching lasts until the User's Watch State of that title next changes (#916); only `hide` sets it. Every other write returns the changes it made, played or not, which `api` tells `WatchStatesChanged` Observers, as the Hub Plugin syncs them (ADR 0008).

### Neighbours

- Uses: `db`, `events`, `requests` (the ADR 0012 call), `playback` (the ADR 0075 call), `users` (`name_key`, which Library names are unique under), `plugins` (`ExtensionPoints`), `images`, `server_settings` (`ImageSettings`).
- Used by: `scanner` and `matching` (also `ListedMovie`, `Recognisers`, `SimilarSources`, `ScanLocks`, `LastScan`, `country_tag`, `PARSER_VERSION` and `METADATA_VERSION`), `browse` (also `OnServer`, `Roles`, `Metadata`, `StoredBoxSet` and `ListedMovie` for a title's page, and `SimilarSources`, `SimilarAnswer`, `merged_similar` and `MAX_SIMILAR` for Similar titles), `playback`, `requests`, `home_rows` (Contents, Libraries, `OnServer`), `watchlist` (`TitleKind`, `matched_ids`), `plugin_settings` (`Libraries`, and `Contents` to delete a disabled Plugin's Similar titles), `automation` (`Contents`, and `title_roles` for `list_titles_sharing`), the `api` parts and startup in `lib.rs`.
