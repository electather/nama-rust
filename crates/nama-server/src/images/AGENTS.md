## Images

The image store: the images the Server keeps, their resized copies and thumbhashes, and the Plugins' Manifest logos kept in it (`plugin_logos.rs`). It keeps the originals through the `Blobs` interface (`blobs.rs`); `LocalDisk` (`local_disk.rs`), files in the data directory, is the default; the Admin may pick a Plugin's blob store instead, which startup in `lib.rs` hands over (`ImageStore::keep_in`), since `images` never calls `plugins`. `serving.rs` sends an original from the store with an `ETag` taken from its key, streamed from a local file where the store has one, and a resized copy from the local cache, made from the original's bytes (ADR 0052).

- **One owner for stored images.** Only `ImageStore` in `crates/nama-server/src/images.rs` reads or writes the image files in the data directory, tests aside (ADR 0037), and `image_thumbhashes`, tests included. The one exception is a backup, which copies `custom-images` whole and puts it back only with the Server stopped (ADR 0068). Artwork and later image kinds go through it. The Server makes one `ImageStore`, since each starts its own resize thread and ADR 0039 allows one; its clones share it. Resized copies live in its `resized` folder and uploads arrive in its `uploads` folder, so no key's first part is either. Startup empties `uploads` (`ImageStore::sweep_uploads`), since only an upload in flight belongs there. A key names its bytes (a title source's path, or a version taken from them): `ImageStore::write` keeps a file already at its key, and browsers keep what `serve` sends for good. A change that stores or removes Matches has `Artwork` delete the images none stores (`drop_unused`) and download those the new ones store (`download_missing`) once it commits, so of downloaded images the store holds what Matches store and nothing else. Custom Images stay until removed, and a Plugin's Manifest logo until another replaces it, even once its Package is gone.
- **Switching stores.** `switch.rs` copies every original under `ORIGINAL_DIRS` to the new store while every write and delete goes to both, under the key's write lock, and makes the new store current only once the caller has saved it; a failure keeps the old one. A new folder of originals gets its constant in `ORIGINAL_DIRS`, or a switch leaves it behind.

### Neighbours

- Uses: `db` and `server_settings` (`ImageSettings`).
- Used by: `artwork`, `custom_images` and `local_images` (the Library area), `playback` (downloaded subtitles, the one kind of stored file that isn't an image, under `DOWNLOADED_SUBTITLES_DIR`), `plugins` (`clean_svg`, `MAX_SVG_BYTES`, and `Blobs` for its Plugin-backed store), `backup` (`CUSTOM_IMAGES_DIR`), the `api` router, `crates/nama-server/src/api/plugins.rs` and `crates/nama-server/src/api/server.rs` (`SwitchImageStore`), and startup in `lib.rs`.
