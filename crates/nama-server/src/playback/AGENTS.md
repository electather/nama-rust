## Playback

Planning how a Device plays a Version, running the plans, serving their files and subtitles, the Tracks, probing and Track Preferences plans are based on, whether a User's next Episode plays by itself, and their Subtitle Appearance and Offsets.

- **What a plan converts is worked out once.** Before the steps run, `candidates` in `../playback.rs` works out what a Remux and a Transcode of the Version would convert, and the plan keeps the one it narrowed to in `Playing`, with the Version's length, which a Remux's or a Transcode's playlist lists, and, for a Transcode on hardware, what it falls back to in software and why. Its reasons, Tracks, events, playlist and ffmpeg arguments read that value; none asks the planning facts again what it converts, how long the Version is or what it falls back to.
- **One path for planning.** Only `plans.rs` (`Plans`) plans a Version for a Device and keeps a Track pick or Subtitle Offset, reading the Preferences it plans by and the Segments, Preview frames and Subtitle Offsets the plan it answers carries; handlers call it.
- **`RunningPlans` knows only running plans.** What ffmpeg can do it reads from the `CanDo` that `Abilities` hands back.
- **One owner for Tracks.** Only `tracks.rs` and its `tracks/` folder read or write `version_probes`, `tracks`, `chapters`, `probe_failures` and `segments`, tests included. Browse attaches them to the Versions `Contents` reads.
- **One path for Segments.** Only `tracks/segments.rs` (`Segments`) reads Chapter names for Segments, asks a `SegmentSource`, in the order a Library lists them, and keeps what they find (ADR 0074, ADR 0075). It asks in the background, never at play time: `Segments::due` works out from what's stored which Versions to ask about, and `Segments::ask` asks about one, safe to run twice, so a jobs system can take over the loop that joins them.
- **One owner for sidecars.** Only `sidecars.rs` reads or writes `sidecar_subtitles` and `downloaded_subtitles`, tests included. A scan says which sidecars each Version has; their language, flags and title come from their names. Every reader of a Version's Tracks, except Probing checking whether to store a probe, reads them with `StoredTracks::of`, which puts its sidecars, then its downloaded subtitles, after the file's own, so those keep their places.
- **One path for downloading subtitles.** Only `downloads.rs` (`SubtitleDownloads`) asks a `SubtitleSource` and writes a download's file, into the blob store under `DOWNLOADED_SUBTITLES_DIR` with a local copy ffmpeg reads; `sidecars.rs` keeps its row (ADR 0067). `Probing::clean_leftovers` deletes the files of Versions gone.
- **One owner for Preview frames.** Only `preview_frames.rs` (`PreviewFrames`) reads or writes `preview_frames`, tests included, makes Preview frames and writes their sheets, into the blob store under `PREVIEW_FRAMES_DIR` (ADR 0076). Which Versions need them is worked out from what's stored, never kept in memory, and making one Version's is safe to run twice, so a jobs system can take either over. `Probing::clean_leftovers` deletes the sheets of Versions gone.
- **One owner for probing.** Only Probing (`probing.rs`, with its private `probing/ffprobe.rs`, `probing/cues.rs` and `probing/mp4.rs`) runs ffprobe on stored files or reads their Cues or sample tables, and maps a failure into what it means for trying it again (`ProbeFailure`); Tracks stores it. Probing is handed what reads a file: its ffprobe adapter runs ffprobe in production, and Probing's tests use the in-memory adapter in `probing/testing.rs`; only tests of the ffprobe adapter itself run a fake program. What any failed read of a Version's file means, for Probing, the text pass or Preview frames, is decided only in `read_failures.rs` (`ReadFailure::of`); each caller only records its answer.
- **One owner for Track Preferences.** Only `track_preferences.rs` reads or writes `track_preferences`, tests included, and decides what a Preference is kept for: the Show or Movie a Version is of, keyed as the per-title rule in `crates/nama-server/AGENTS.md` says (ADR 0035).
- **One owner for autoplay.** Only `autoplay.rs` reads or writes `autoplay_off`, tests included.
- **One owner for Subtitle Appearance.** Only `subtitle_appearance.rs` reads or writes `subtitle_appearances`, tests included. It's no plan input, so a Burn-in never takes it (ADR 0070).
- **One owner for Subtitle Offsets.** Only `subtitle_offsets.rs` reads or writes `subtitle_offsets`, tests included, and decides what names a Track for good: a sidecar's or download's path, else its place (ADR 0070). It's no plan input either.
- **Probe version.** A change to what probing reads from a file, or how, bumps `PROBE_VERSION` in `tracks.rs`, so the next pass after a scan probes every file again (ADR 0023's pattern).
- **Probe failure version.** A change that may let ffprobe read files it lastingly failed on before, without changing what probing reads from a file that it could read, bumps `PROBE_FAILURE_VERSION` in `tracks.rs`, so the next pass tries again only those files, and the next Remux lists the keyframes it couldn't before.
- **WebVTT version.** A change to the WebVTT a subtitle source makes bumps `WEBVTT_VERSION` in `subtitles.rs`, so what the cache kept from before is made again.

### Neighbours

- Uses: `ffmpeg`, `library`, `server_settings` (its settings and `PlaybackLimit`), `events`, `images` (also keeping downloaded subtitles and Preview frames), `plugins` (`ExtensionPoints`, asking subtitle and Segment sources), `users`, `db`, `diagnostics` (the trace a probe pass joins), and `config` in tests.
- Used by: `api`, `browse`, `scanner` and startup in `lib.rs`.
