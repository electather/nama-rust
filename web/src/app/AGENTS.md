## web/src/app

The shell: the layouts the layout routes render, the app chrome, and what a route shows when it fails. Its queries and mutations are data hooks in `data/`, one per file, like a feature's.

- **The `_member` layout hosts "Confirm it’s you".** `MemberLayout` wraps every signed-in page in `ConfirmItsYou`, the one dialog `useSensitiveMutation` opens. A page never renders its own. At the Hub, an Account's pages sit in the signed-out frame instead, and Home under no chrome, until the Hub gives them chrome (#2204), so none of them may call `useSensitiveMutation`. A Server's pages at the Hub get their own from the `_member/_server` layout, and a Server's Settings picked there theirs from `SettingsBody`, each showing `SignInOnHubDialog`. A change to the Account there shows the Hub's Recent Authentication refusal with `HubRefusal`, which offers to sign in again, and takes `useSignInIfSessionEnded()` as its `onError`.
- **The `_member` layout hosts Settings.** `SettingsLoader` renders the Settings modal over whichever page `?settings=<section>` is on, loading its code only then. A link opens Settings by adding that word to the address of the page it's on (`to="."`), never by going to a page of its own.
- **`fullScreen` leaves out the app chrome.** A route that sets `staticData: { fullScreen: true }` (declared in `src/router.tsx`), such as the player's, gets no app chrome once it has loaded. One that failed keeps it, so its error or not-found page has a way out. At the Hub, one that sets `fillsTheHub`, such as the Watchlist, fills the screen as a Server's pages do, out of the Account's card.
- **Diagnostics load before the page.** The `_member` route's `beforeLoad` awaits `recordDiagnosticsIfExported` (`src/shared/lib/diagnostics.ts`), so the page's own calls are traced too. It loads the OpenTelemetry SDK only while the Server exports Diagnostics, and only `src/shared/lib/diagnostics-recorder.ts` imports the SDK, so it stays a chunk of its own (ADR 0054).
