# web

The web app: React and TanStack Start in SPA mode, built into static files that the Server embeds and serves (ADR 0004). The decisions behind it are in issue #27 and ADRs 0016 and 0017. The web app shell issue (#28) sets up everything described here.

## Toolchain

Everything runs through [Vite+](https://viteplus.dev) (`vp`, ADR 0017). It pins Node 26 and pnpm 12 for this package, so install `vp` and run:

```sh
vp env install   # the pinned Node and pnpm
vp install       # dependencies
```

| Job                                              | Command                                        | Tool underneath                    |
| ------------------------------------------------ | ---------------------------------------------- | ---------------------------------- |
| Dev server                                       | `vp dev`                                       | Vite                               |
| Build                                            | `vp build`                                     | Vite (Rolldown), output in `dist/` |
| Format, lint, type-check                         | `vp check` (`vp check --fix` to apply fixes)   | oxfmt, oxlint, tsgo                |
| Tests                                            | `vp test`                                      | Vitest on happy-dom                |
| Unused code, duplication, complexity, boundaries | `vp run fallow`                                | Fallow                             |
| Design check                                     | `impeccable detect --json <files>` (repo root) | impeccable                         |

All lint, type-check and Fallow config lives in `vite.config.ts`, `tsconfig.json` and the Fallow config. There is no `.oxlintrc`. pnpm's own settings (`minimumReleaseAge`, the allowlist for dependency build scripts, and `runtimeOnFail`/`pmOnFail` set to `ignore` so pnpm leaves Node and pnpm versions to `vp`) are in `pnpm-workspace.yaml`.

## Checks

CI's `web` job runs, and every finding fails it:

```sh
vp check
vp test
vp build
vp run fallow   # fallow --ci
(cd .. && impeccable detect --json web/src)
```

impeccable runs from the repo root because that's where it finds `.impeccable/config.json`, which ignores `src/gen/`, and `DESIGN.md`. From `web/` it reads neither.

How strict they are:

- **oxlint**: the `typescript`, `react`, `jsx-a11y`, `import`, `unicorn`, `promise` and `oxc` plugins, plus `vitest` for tests, and [`@shadcn/lint`](https://github.com/shadcn-ui/lint) for the design system: no raw palette colours, arbitrary values, inline styles, unknown or dynamic classes, or `className` restyles of `src/components/ui/` components. The `correctness`, `suspicious`, `pedantic` and `perf` categories are on in full, plus picked `restriction` rules. Every rule is `error`, never `warn`. A rule that turns out to be noise is turned off in `vite.config.ts` with a comment saying why.
- **TypeScript**: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `noPropertyAccessFromIndexSignature`, `verbatimModuleSyntax`, `isolatedModules` and `erasableSyntaxOnly`. Unused locals are reported by oxlint, not tsc.
- **Fallow**: every rule is `error`, except `coverage-gaps`, which needs the runtime coverage sidecar. Any duplicated code fails. The complexity limits are 15 cyclomatic and 15 cognitive. Generated code is ignored, and so are unused exports in `src/components/ui/`, since shadcn files export every sub-part. An unused file there still fails.

## Generated client

`src/gen/` holds the TypeScript messages and service descriptors that `protoc-gen-es` generates from `proto/` (ADR 0007). Like the Rust code in `crates/nama-proto`, it's checked in, and CI's `lint` job fails if it's stale. After changing the schema, run `vp install` here (that installs the plugin), then `buf generate` in `proto/`. Calls go through `@connectrpc/connect-query` with the generated descriptors, so there's no `protoc-gen-connect-query`.

## Running against a Server

Start a Server (it listens on `http://localhost:7980` by default), then run `vp dev`. The dev server proxies every Connect path (`/nama.…`) and `/media/…` to `NAMA_SERVER_URL`, which defaults to that address. The browser sees one origin, so the `SameSite=Strict` session cookie works as it does in production and no CORS is involved (ADR 0015).

Tests never need a Server. They fake RPCs with Connect's `createRouterTransport`, built from the same generated descriptors.

## How the app is put together

- **Data**: all server state goes through connect-query and TanStack Query. Route loaders prefetch with `queryClient.query({ …, staleTime: "static" })`, which only fetches what isn’t cached yet. One app-wide `Subscribe` stream turns Events into query invalidations. There's no client-state library and no form library: forms are native `<form>`s with mutations, the Server validates, and Connect error details are shown next to the field.
- **Errors**: a global query and mutation error handler sends `unauthenticated` to `/sign-in?redirect=…`. `permission_denied` shows a "You can’t open this page" page. Anything else shows the route's `errorComponent` in plain words, never an error code. A page whose loader throws `notFound()`, such as an unknown Movie, sets its own `notFoundComponent`: the router only looks for one from the throwing route upwards, and without it the root's replaces the app chrome too.
- **Sensitive changes**: `useSensitiveMutation` (`src/components/confirm-its-you.tsx`) calls an RPC that needs Recent Authentication. When the Server refuses with the `RECENT_AUTHENTICATION_REQUIRED` Refusal, it opens the one "Confirm it’s you" dialog, which the `_member` layout holds, calls `Reauthenticate` with the password and retries the call once. A second refusal is an ordinary error. Cancelling fails the call with `canceled`, which `refusal()` (`src/lib/forms.ts`) shows as nothing, so the form stays as it was. Nothing asks before the Server refuses: it alone keeps the clock.
- **Styling**: Tailwind v4 and shadcn on Base UI, with tokens in `src/styles.css` (ADR 0016). Lucide icons. `components.json` holds the `shadcn init -t start -b base` choices, but the packages `init` installs (`@base-ui/react`, `class-variance-authority`, `cn`, `lucide-react`) aren't installed until a screen uses a component, since Fallow fails on unused dependencies. `shadcn add` installs only `cn`, so `vp add` the others a new component imports. Fonts are Google Fonts families bundled through Fontsource, never loaded from Google's CDN. Dark only for now. English only, with no i18n library, but layout uses logical properties so right-to-left languages can be added later.
- **Player**: a native `<video>` playing the URL of the Playback Plan it asks the Server for on opening (`usePlaybackPlan`), sending what the browser says it decodes just then, which nothing stores, with controls built from Base UI primitives, and a "Playback info" panel that shows the plan's method, Tracks and reasons. The plan's subtitles are ones the Device shows itself, so picking one never asks for a new plan: text ones are `<track>`s that `useSubtitles` shows or hides, and `useDrawnSubtitle` draws PGS ones over the video with libbitsub, and ASS ones with the fonts their file carries with `@jellyfin/libass-wasm`, fetching each renderer only then. The web app says it draws PGS whenever the browser has WebAssembly, and ASS when it also has Web Workers, until a format's renderer fails, when it asks for a plan that burns the Track in instead (ADR 0033). Only libass's WebAssembly worker is built in, which `useDrawnSubtitle` starts from a blob that tells it where the build put its `.wasm`, and a build plugin in `vite.config.ts` ships its notices. A Remux or Transcode plays an HLS playlist. `usePlaybackSource` gives it straight to the `<video>` where the browser plays HLS itself (`playsHlsNatively`), and otherwise plays it through hls.js, which it fetches only then. Its routes set `staticData: { fullScreen: true }`, which tells the `_member` layout to leave out the app chrome. A plan that can’t play shows its reasons, and a file the browser can’t play anyway a message, not a broken player.
- **Watch State**: `<Player>` hands its `<video>`, the Version and the title's Watch State to `useWatchState` (`src/lib/watch-state.ts`). It resumes where you stopped and reports in the background, retrying failures without showing them. Posters and Episodes show it with `src/components/watch-state.tsx`.

While the Server needs setup, every page redirects to `/setup`. A pathless `_member` layout requires a session, and an `_admin` layout inside it requires the Permission that `adminPages` (`src/lib/access.ts`) lists for the page. The Admin Permission covers them all. Put a signed-in page under `src/routes/_member/`, and an Admin page under `src/routes/_member/_admin/`. These checks run in the `beforeLoad` of `/setup`, `/sign-in` and `_member`, through `src/lib/access.ts`, not in the root's: the build prerenders the root into the SPA shell, and the browser reuses what the root's `beforeLoad` returned there instead of running it again. Movie and Show IDs in URLs are the external IDs the API returns. When no `version` is given, the player plays the largest Version.

## Tests

Vitest with Testing Library on happy-dom. Test behaviour (redirects, forms, error and empty states), not markup snapshots. There's no end-to-end suite in M2.
