# web

The web app: React and TanStack Router, built with Vite into static files that the Server embeds and serves (ADRs 0004 and 0063). The decisions behind it are in issue #27 and ADRs 0016 and 0017. The web app shell issue (#28) sets up everything described here.

## Toolchain

`web/` is a pnpm workspace of three packages (ADR 0101):

- **The web app**, at the root: everything below unless it says otherwise.
- **nama-ui**, in `ui/`: the design system, which both apps share. Its shadcn components are in `ui/src/components/`, and its tokens and fonts in `ui/src/styles.css`. It has no build step: its `exports` point at its sources, which each app's Vite compiles. Shared components, hooks and helpers that aren't the design system stay in the web app's `src/shared/`.
- **The Hub web app**, nama-hub-web, in `hub/`: the Hub's pages for Accounts (ADR 0010), which the Hub embeds and serves. Its code is in `hub/src/`, imported through its own `@hub/` alias, with a route per page in `hub/src/routes/` and the rest in `hub/src/app/` and `hub/src/features/`. It builds to the same `DESIGN.md`.

The packages pin a dependency more than one declares once, in `pnpm-workspace.yaml`'s `catalog`. Every command below runs from `web/` and covers all three. `vp build` builds the web app at the root into `dist/`, the files the Server embeds, and `vp -C hub build` the Hub web app into `hub/dist/`, the files the Hub embeds. `hub/vite.config.ts` holds only what its build needs; its checks and tests run from the root's config.

Everything runs through [Vite+](https://viteplus.dev) (`vp`, ADR 0017). It pins Node 26 and pnpm 12 for this workspace, so install `vp` and run:

```sh
vp env install   # the pinned Node and pnpm
vp install       # dependencies
```

| Job                                              | Command                                                     | Tool underneath                    |
| ------------------------------------------------ | ----------------------------------------------------------- | ---------------------------------- |
| Dev server                                       | `vp dev`                                                    | Vite                               |
| Build                                            | `vp build`                                                  | Vite (Rolldown), output in `dist/` |
| Format, lint, type-check                         | `vp check` (`vp check --fix` to apply fixes)                | oxfmt, oxlint, tsgo                |
| Tests                                            | `vp test`                                                   | Vitest on happy-dom                |
| Unused code, duplication, complexity, boundaries | `vp run fallow`                                             | Fallow                             |
| Design check                                     | `vp dlx impeccable@4.8.0 detect --json <files>` (repo root) | impeccable                         |

All lint, type-check and Fallow config lives in `vite.config.ts`, `tsconfig.json` and the Fallow config. There is no `.oxlintrc`. pnpm's own settings (`minimumReleaseAge`, the allowlist for dependency build scripts, and `runtimeOnFail`/`pmOnFail` set to `ignore` so pnpm leaves Node and pnpm versions to `vp`) are in `pnpm-workspace.yaml`.

## Checks

CI's `web` job runs, and every finding fails it:

```sh
vp check
vp test
vp build
vp -C hub build
vp run fallow   # fallow --ci
(cd .. && vp dlx impeccable@4.8.0 detect --json web/src web/ui/src web/hub/src)
```

impeccable runs from the repo root because that's where it finds `.impeccable/config.json`, which ignores `src/gen/` and `hub/src/gen/`, and `DESIGN.md`. From `web/` it reads neither.

How strict they are:

- **oxfmt**: formats, sorts imports, and sorts Tailwind classes against each package's own stylesheet (`src/styles.css`, `ui/src/styles.css`), in `className` and in `cn` and `cva` calls. No lint rule checks either order.
- **oxlint**: the `typescript`, `react`, `jsx-a11y`, `import`, `unicorn`, `promise` and `oxc` plugins, plus `vitest` for tests. Two ESLint plugins run inside it: [`@shadcn/lint`](https://github.com/shadcn-ui/lint) for the design system (no raw palette colours, arbitrary values, inline styles, unknown or dynamic classes, or `className` restyles of nama-ui's components) and [`eslint-plugin-better-tailwindcss`](https://github.com/schoero/eslint-plugin-better-tailwindcss) for classes that conflict, repeat, are deprecated or have a canonical or shorter spelling, and for left/right classes ("Logical properties" in `AGENTS.md`). Every category is on in full, `nursery`, `style` and `restriction` included. Every rule is `error`, never `warn`. A rule left off, such as one that's taste only or one Fallow already covers, is turned off in `vite.config.ts` with a comment saying why.
- **TypeScript**: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `noPropertyAccessFromIndexSignature`, `verbatimModuleSyntax`, `isolatedModules`, `erasableSyntaxOnly`, `forceConsistentCasingInFileNames`, and unreachable code and unused labels as errors. Unused locals are reported by oxlint, not tsc.
- **Fallow**: every rule is `error`, except `coverage-gaps`, which needs the runtime coverage sidecar. Any duplicated code fails. The complexity limits are 15 cyclomatic and 15 cognitive, and a file holds at most 200 lines (400 for a test in `__tests__/`). Zones enforce which folder imports which, and the rule pack in `fallow-rules.jsonc` enforces data hooks, Suspense and dynamic loading in `src/app/`, `src/features/` and `src/shared/`. Generated code is ignored. nama-ui's package `exports` make each of its components an entry point, so an unused one, or an unused sub-part, fails as an unused export (`includeEntryExports`).
- **`src/app/`, `src/features/`, `src/shared/` and `ui/src/`** get stricter oxlint rules on top, listed in `AGENTS.md`.

## Generated client

`src/gen/` holds the TypeScript messages and service descriptors that `protoc-gen-es` generates from `proto/` (ADR 0007). It holds the client API, and the Hub API, `nama.hub.v1`, which the app calls when it runs at the Hub (ADR 0105), not the Plugin contract. The Hub web app's `hub/src/gen/` holds the Hub API, `nama.hub.v1`, only. Like the Rust code in `crates/nama-proto`, it's checked in, and CI's `lint` job fails if it's stale. After changing the schema, run `vp install` here (that installs the plugin), then `buf generate` in `proto/`. Calls go through `@connectrpc/connect-query` with the generated descriptors, so there's no `protoc-gen-connect-query`.

## Running against a Server

Start a Server (it listens on `http://localhost:7980` by default), then run `vp dev`. The dev server proxies every Connect path (`/nama.…`), `/media/…`, `/custom-images/…` and `/diagnostics/…` to `NAMA_SERVER_URL`, which defaults to that address. The browser sees one origin, so the `SameSite=Strict` session cookie works as it does in production and no CORS is involved (ADR 0015).

To see the web app as it runs at the Hub (ADR 0105), start a Hub too and run `NAMA_HUB_URL=http://localhost:7981 vp dev`: the dev server then proxies the Hub's Connect paths (`/nama.hub.…`) to it, and the app, finding the Hub's API answer, signs an Account in instead of a User.

For the Hub web app, start a Hub (`crates/nama-hub/README.md`, listening on `http://localhost:7981`), then run `vp -C hub dev`, which proxies the Hub's Connect paths (`/nama.hub.…`) to `NAMA_HUB_URL`, which defaults to that address.

Tests never need a Server or a Hub. They fake RPCs with Connect's `createRouterTransport`, built from the same generated descriptors.

## Installing as an app

`public/` holds the web app manifest, icons and the push-only service worker `push-worker.js` (`AGENTS.md`), which the build copies as they are and the Server serves. Chrome installs the app in a window of its own only from a secure origin, HTTPS or `localhost`: from a Server on plain `http://` on the LAN it adds a shortcut that opens in a browser tab. iOS "Add to Home Screen" works either way. Per-Server certificates, which fix that, come through the Hub (ADR 0010, ADR 0057).

The icon is `public/icon.svg`, a Geist SemiBold "N" as a path, which is also the favicon. After changing it, render the PNGs again from `web/`:

```sh
playwright screenshot --viewport-size 192,192 "file://$PWD/public/icon.svg" public/icon-192.png
playwright screenshot --viewport-size 512,512 "file://$PWD/public/icon.svg" public/icon-512.png
playwright screenshot --viewport-size 180,180 "file://$PWD/public/icon.svg" public/apple-touch-icon.png
```

## JASSUB's notices

`public/licenses/jassub.txt` holds the notices of the libraries JASSUB bundles, which its npm package doesn't carry. After bumping `jassub`, generate it again from a clone of [JASSUB](https://github.com/ThaUnknown/jassub) at the commit the release was built from, with its submodules, and [`licensecheck`](https://metacpan.org/dist/App-Licensecheck) on `PATH`:

```sh
make -f Makefile_licence LIB_LICENSES="brotli freetype fribidi harfbuzz libass"
cat dist/license/all.tmp build/license_fullnotice > path/to/web/public/licenses/jassub.txt
```

`LIB_LICENSES` leaves out expat, which the Makefile still lists but JASSUB no longer bundles. The Makefile's own lint step can fail after `all.tmp` is written, and the `# Project: jassub` section comes out empty, so copy the copyright lines of JASSUB's `LICENSE` into it by hand. The Makefile also misses mimalloc, which Emscripten links into `jassub-worker-modern.wasm`, so add its `# Project: mimalloc` section by hand too, from the `LICENSE` in Emscripten's `system/lib/mimalloc`.

`public/licenses/liberation-sans.txt` is the [Liberation fonts](https://github.com/liberationfonts/liberation-fonts) `LICENSE` (OFL 1.1), for JASSUB's fallback font `dist/default.woff2`. OFL 1.1 condition 2 asks each copy of the font to carry it, and the font's metadata names the license but doesn't hold its text. If a `jassub` bump changes that font, copy the `LICENSE` of its release again.

## How the app is put together

The app is organised by feature (ADR 0064). [`src/AGENTS.md`](src/AGENTS.md) has the layout, which folder imports which, and the rules for each folder.

- **Data**: all server state goes through connect-query and TanStack Query. Route loaders prefetch with `queryClient.query({ …, staleTime: "static" })`, which only fetches what isn’t cached yet. The hooks that read that data pass `loaderStaleTime` (30 s), so a page that mounts late doesn't ask again, while a revisit or window focus after that refetches in the background. One app-wide `Subscribe` stream turns Events into query invalidations. There's no client-state library and no form library: forms are native `<form>`s with mutations, the Server validates, and Connect error details are shown next to the field.
- **Errors**: a global query and mutation error handler sends `unauthenticated` to `/sign-in?redirect=…`. `permission_denied` shows a "You can’t open this page" page. Anything else shows the route's `errorComponent` in plain words, never an error code. A page whose loader throws `notFound()`, such as an unknown Movie, sets its own `notFoundComponent`: the router only looks for one from the throwing route upwards, and without it the root's replaces the app chrome too.
- **Sensitive changes**: `useSensitiveMutation` (`src/shared/hooks/use-sensitive-mutation.ts`) calls an RPC that needs Recent Authentication. When the Server refuses with the `RECENT_AUTHENTICATION_REQUIRED` Refusal, it opens the one "Confirm it’s you" dialog, which the `_member` layout holds, calls `Reauthenticate` with the password and retries the call once. On a Server Linked to the Hub the dialog also offers "Sign in with your Account", for a User with no password: the Hub sends the browser back to `/reauthenticate/account`, which calls `Reauthenticate` with the Account's approval and goes back to the page, where the change is made again. A second refusal is an ordinary error. Cancelling fails the call with `canceled`, which `refusal()` (`src/shared/lib/forms.ts`) shows as nothing, so the form stays as it was. Nothing asks before the Server refuses: it alone keeps the clock.
- **Styling**: Tailwind v4 and shadcn on Base UI, with tokens in nama-ui's `ui/src/styles.css` (ADR 0016). Lucide icons. `components.json` holds the `shadcn init -t start -b base` choices, and `ui/components.json` repeats them for nama-ui. `ui/node_modules/.bin/shadcn add <component>`, run from `web/`, writes the component to `ui/src/components/`. The packages `init` installs (`@base-ui/react`, `class-variance-authority`, `cn`, `lucide-react`) aren't installed until a screen uses a component, since Fallow fails on unused dependencies. `shadcn add` installs only `cn`, so add the others a new component imports to `ui/package.json`. Fonts are Google Fonts families bundled through Fontsource, never loaded from Google's CDN. Dark only for now. English only, with no i18n library, but layout uses logical properties so right-to-left languages can be added later.
- **Player**: `src/features/player/AGENTS.md` has how it plays, draws subtitles and reports Watch State.
- **Diagnostics**: only while the Server says it exports them (`GetServerInfo`'s `exportsDiagnostics`), the `_member` layout loads the OpenTelemetry SDK, which `src/shared/lib/diagnostics-recorder.ts` alone imports, as a chunk of its own (ADR 0054). From then on the transport's interceptor runs each ConnectRPC call in a span and sends its `traceparent`, and route changes, playback start and uncaught errors get spans too, which go to the Server's `/diagnostics/v1/traces`.
- **Watch State**: `<Player>` hands its `<video>`, the Version and the title's Watch State to `useWatchState` (`src/features/player/hooks/use-watch-state.ts`). It resumes where you stopped and reports in the background, retrying failures without showing them. Posters, Continue Watching cards, Episodes and the Play or Resume pill on a title's page show it with the components in `src/shared/components/watch-state/`.

While the Server needs setup, every page redirects to `/setup`. A pathless `_member` layout requires a session. Settings shows only the sections the User's Permissions open (`needs` in `src/features/settings/lib/sections.ts`), and the top bar's and action bar's Admin open it at the first section past You and Preferences. The Admin Permission opens every section. `src/routes/AGENTS.md` says where a page goes and where these checks run. Movie and Show IDs in URLs are the external IDs the API returns. When no `version` is given, the player plays the largest Version.
